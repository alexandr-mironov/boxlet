# Совместимость

Boxlet предоставляет стандартный Docker Engine API и совместим
с инструментами, которые ожидают «настоящий» Docker.

Каждый пункт ниже проверяется командой `boxlet doctor`.

## 1. Docker Engine API

- [x] `docker version` проходит, актуальный API (Docker Engine 29)
- [x] поддерживаются hijack/upgrade-соединения (`docker run -it`,
      `docker exec`, attach-потоки, testcontainers)

## 2. Сокет

- [x] `~/.boxlet/run/docker.sock` слушает и отвечает (права 0600)
- [ ] `/var/run/docker.sock` — симлинк на него: создаётся автоматически
      при старте, если установлен setuid-хелпер (`boxlet priv install`,
      один раз с GUI-запросом пароля), либо вручную по подсказке
      из `boxlet doctor`

## 3. TLS до dockerd

- [x] dockerd в гостевой ОС доступен только по mTLS (tlsverify);
      комплект сертификатов выпускается в `~/.boxlet/certs` при первом
      запуске автоматически. Для пользователя это прозрачно: docker CLI
      ходит на unix-сокет, TLS живёт только между прокси и гостем
- [ ] проверка отклонения plain HTTP и TLS без клиентского сертификата
      в `boxlet doctor`

## 3. Сети

- [x] сети из `auto_networks` в конфиге создаются автоматически при старте
- [x] проброс портов контейнеров на 127.0.0.1: на бэкенде darwin-vz —
      автоматически для всех портов, опубликованных запущенными
      контейнерами (`-p 8080:80`, включая случайные хостовые порты),
      плюс статический список `forwarded_ports` в `~/.boxlet/config.json`;
      проброс снимается при остановке контейнера. Порты <1024 из
      `forwarded_ports` пробрасывает setuid-хелпер `boxlet-priv`
      (установка: `boxlet priv install`, один раз с паролем
      администратора через GUI-диалог macOS). На qemu-бэкенде —
      только статический список через hostfwd, порты <1024 недоступны

## 4. Реестры

- [x] `~/.docker/config.json` читается docker CLI как обычно
      (boxlet не подменяет DOCKER_CONFIG)

## 5. Архитектуры

- [x] образы linux/amd64 на Apple Silicon: на бэкенде darwin-vz через
      Rosetta в гостевой ОС (проверено: `--platform linux/amd64`);
      на qemu-бэкенде возможна эмуляция qemu (медленно, не настроено)

## 6. Доступ к файлам

- [x] bind-mount каталогов хоста (`docker run -v $PWD:/src ...`) —
      на бэкенде darwin-vz через virtiofs (каталоги из `mounts` в конфиге
      видны в гостевой ОС по тем же путям); на qemu-бэкенде недоступно

## 7. DNS

- [x] зона `*.boxlet.local` резолвится в адрес гостевой ОС
      (активируется `boxlet dns install`; к опубликованным портам
      контейнеров можно обращаться, например, `web.boxlet.local:8080`)

## Известные ограничения darwin-vz (M2)

- порты <1024 требуют setuid-хелпер (`boxlet priv install`); порты также
  всегда доступны напрямую по IP гостя (`boxlet status` показывает его)
- `boxlet shell` работает через гостевой агент (boxlet-agent), но без pty —
  интерактивный sh в строчном режиме

## Известные ограничения qemu-бэкенда (M1)

- проброс портов только статическим списком, без <1024 без root
- нет bind-mount с хоста (данные контейнеров живут в VM на qcow2-диске)
